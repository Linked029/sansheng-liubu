## 架构共识（grilling 输出）

### 双轨采集通道

| 轨道 | 来源 | 频率 | 候选队列 | 审批方式 |
|------|------|------|----------|----------|
| 固定源 | 用户配置的 RSS/URL/手动 | 每日（按部 cron） | 常规候选池 | 日常审批 |
| AI 探索 | 用户每周输入方向 → AI 拆搜索词 → 本地搜索 | 每周 | **探索卷宗** | 集中浏览后手动归档 |

### 探索卷宗闭环

方向输入（人）→ 搜索词拆分（AI）→ 本地搜索引擎捞取 → 探索卷宗（独立浏览）→ 手动归档 → 自动反哺：
- 归档内容的语义簇纳入兴趣图谱
- 连续归档两次的同源建议加为固定源

### 三层自动化过渡机制

1. **硬规则层** — 用户确认的闸门（总是准奏/驳回/排除清单），可解释可编辑
2. **AI 多维打分** — 四维度权重从审批历史在线学习，只排序不截断
3. **嵌入探索轨** — 近似推荐 + 低相似度破茧推荐，配额制保底

### 隐私立场

- 敏感内容不出本机
- embedding 和搜索优先本地（SearXNG / sqlite-vec）
- 云端 API 作为升级项

## 新增模块

### Server

| 文件 | 说明 |
|------|------|
| `server/src/exploration.ts` | 探索卷宗三张新表 schema 迁移 + 全部 CRUD（search_directions / search_terms / exploration_items） |
| `server/src/search.ts` | DuckDuckGo HTML 搜索引擎 + 管线（方向→AI拆词→逐词搜索→去重入库→建议固定源） |

### Web

| 文件 | 说明 |
|------|------|
| `src/ui/screens/ExplorationPane.tsx` | 探索卷宗页面：方向输入、AI拆词触发、搜索结果浏览、归档/丢弃 |

### 新增 API 端点（7 个）

- `POST /api/exploration/directions` — 创建方向
- `GET /api/exploration/directions` — 列出方向
- `POST /api/exploration/directions/:id/run` — 触发搜索管线
- `GET /api/exploration/items` — 列出卷宗条目
- `POST /api/exploration/items/:id/archive` — 归档条目
- `POST /api/exploration/items/:id/dismiss` — 丢弃条目
- `GET /api/exploration/suggestions` — 建议固定源

## Bug 修复

| 问题 | 根因 | 修复 |
|------|------|------|
| 信息源 4 次提取失败 | source kind=feed 但 location 是微信 URL（非 RSS），rss-parser 解析 HTML 报错 | `fetcher.ts` 新增降级：feed 解析失败且 location 像 URL 时自动回退到 URL 抓取 |
| 自动准奏跳过门下省 | autoApproveThreshold 默认 3，AI 评分 85 直接归档 | 默认改为 0（关闭自动准奏），用户可手动调整 |
| 门下省红点无法消除 | Service Worker 缓存旧 JS | SW 缓存升级到 v3，旧缓存自动清理 |
| 工作台数据不显示 | DashboardPane 首次加载时服务未就绪就永久空白 | 新增自动重试（5 次，间隔 1 秒） |
| MemorialReader 预览切回奏折空白 | canvas useEffect 缺少 viewMode 依赖 | 添加 viewMode 到依赖数组 |
| MemorialReader 标题被 UI 遮住 | 封面标题 y 位置偏上 | 标题 y:78→88，顶部装饰同步下移 |
| 门下省阅读体验差 | 全文默认折叠、展开按钮太隐蔽 | 全文 Markdown 渲染、摘要 line-clamp 截断、按钮改为显式图标 |
